## Cove Windows Toolkit v3.4.1

Tester feedback release: an on/off switch for every tweak, portable state that
actually stays with the portable executable, and fixes for four issues reported
against v3.4.0.

### New

**CPU temperatures are back, as an opt-in**
- CPU sensors need a kernel-mode driver. Builds before 2.2.0 installed one
  (PawnIO) silently during diagnostics; 2.2.0 compiled that path out, which is
  why CPU readings disappeared. Cove now reads CPU sensors again through
  LibreHardwareMonitor whenever the driver is already present, and offers an
  "Enable CPU sensors" button on the Temperatures screen when it is not.
- The install happens only after an explicit confirmation that names the driver
  and says it stays installed until removed through Apps & Features. No scan,
  cleanup, or diagnostic path can install it, and the install is recorded in the
  support log.
- The sensor library and the driver installer are staged under `%SystemRoot%\Temp`,
  which only administrators can write to. The previous implementation staged them
  in the per-user temp directory and loaded them from there while running
  elevated, which a medium-integrity process could have hijacked.
- GPU temperatures now come from the sensor provider when it is available, with
  nvidia-smi as the fallback, so non-NVIDIA cards report too.
- Bundled components and their licences are recorded in `THIRD-PARTY-NOTICES.md`.

**Every tweak is now a switch**
- Visual, performance, and privacy tweaks each have an on/off switch. Switching
  one off restores the exact value it had before Cove changed it - including
  removing the value entirely if it did not exist beforehand.
- Privacy tweaks could not be reverted from the panel at all before this; they
  now behave like the other two panels.
- Each panel has a "Revert All (n)" action that puts every change Cove made on
  that panel back, so applying a batch of tweaks is no longer a one-way door.
- A tweak that is already on but was set outside Cove shows a locked switch
  labelled "no saved original" instead of pretending it can be reverted. Service
  changes stay non-revertable and still point at the Services panel.

**Portable builds keep their state beside the executable**
- `Cove-Windows-Toolkit-*-Portable.exe` now stores logs, rollback data, history,
  and machine snapshots in `cove-app-data\cove-windows-optimizer\` next to
  itself instead of per-user AppData. Any other copy opts in with an empty
  `portable.marker` file beside it.
- Because the app runs elevated, the adjacent directory is created by Cove and
  re-checked on every write: if any component is a reparse point (junction,
  symlink, or any other tag) portable mode is refused and the app falls back to
  AppData with the reason recorded in the support log. This was the concern that
  disabled adjacent storage in 3.4.0; it is now enforced in code and covered by a
  test that plants a real junction.

### Bugs fixed

**Support log flooded with false failures**
- The IPC wrapper treated any result carrying a `success` field as a command
  status envelope. `get_scan_progress` reports the *scan's* outcome, so it is
  `false` for as long as a scan runs; polled four times a second it wrote
  `command_reported_failure detail=get_scan_progress: undefined` continuously and
  pushed every genuine entry out of the support log. Payloads with a domain
  `success` field are now excluded from envelope reporting.

**Speed test failed on every machine**
- The download ran under Windows PowerShell 5.1, which does not load
  `System.Net.Http` by default, so `[System.Net.Http.HttpClient]` never resolved
  and the test reported a bare failure. The assembly is now requested explicitly
  and TLS 1.2 is pinned. Failures also report why instead of showing only
  "Check your internet connection".

**Temperatures screen was empty**
- GPU temperatures were looked up only at
  `%ProgramFiles%\NVIDIA Corporation\NVSMI\nvidia-smi.exe`, a path current NVIDIA
  drivers no longer create. They install `nvidia-smi.exe` into System32. Both
  absolute locations are checked now (still never resolved through the process
  search path).
- Disk temperatures were added from the storage reliability counters that Disk
  Health already reads, cached for 20 seconds so auto-refresh does not re-query
  the storage stack every three seconds.
- The "CPU sensor provider is not installed" notice appeared even when readings
  were available. It now shows only when no CPU reading exists, and points at the
  opt-in above.
- Removed a leftover 4-second retry loop that re-queried sensors forever while
  waiting for a sensor provider that is no longer launched.

**DISM / SFC scans could appear to hang**
- If the pseudo-console reader gave up while the tool was still running, nothing
  drained the console buffer, the tool blocked on its next write, and the scan
  sat at a frozen percentage until the two-hour deadline. The tool is now
  cancelled immediately and the run is reported as failed.
- Scans write start, one-minute progress, and completion lines to the support log
  (percent, phase, elapsed, exit code), so a stalled scan can be told apart from
  a slow one.
